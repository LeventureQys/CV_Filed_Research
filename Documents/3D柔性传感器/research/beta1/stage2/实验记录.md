## 4. 算法分析

### 4.1 为什么统计门限法失败

Stage1 的 `stat_k3` 算法核心逻辑：
```
residual = frame - baseline (median)
threshold = k_sigma * noise_std
out = residual if residual >= threshold else 0
```

对于 64×64 膜片：
- 背景 ADC=0 → baseline=0 → residual=frame
- 压力信号幅度 100-800 ADC，噪声 σ=5-20
- threshold = k * σ = 15-60
- 低幅值触点（如 150 ADC 的低 SNR 数据）被全部切除
- 即使高幅值触点，边缘区域也被误切

**结论**：幅值门限对 64×64 膜片完全不适配。

### 4.2 最佳算法 `avg3+median3+gauss`

**算法流程**：
1. 多帧平均（窗口=3）→ 抑制帧间随机噪声
2. 时域中值滤波（窗口=3）→ 去除异常帧
3. 空间高斯滤波（σ=1.5）→ 利用空间邻域平滑噪声

**优势**：
- 无 baseline 假设（不依赖背景噪声统计）
- 利用时间相关性（帧间平滑）
- 利用空间相关性（邻域平滑）
- 3 个步骤正交，彼此互补

**局限**：
- 低 SNR 场景（CS=0.78）仍有明显提升空间
- 高斯滤波会模糊压力边界（但对大面积接触影响小）

### 4.3 低 SNR 场景 (`temporal5+adaptive`)

对于 `low_snr_small_patches`（SNR 仅 2.64dB），最佳方案是 `temporal5+adaptive`（CS=0.8062），说明：
- 更长的时域窗口（5帧）有助提取弱信号
- 自适应空间滤波（根据局部方差调整平滑强度）优于固定高斯核

## 5. 结论与建议

### 5.1 对 64×64 膜片的推荐算法

| 噪声等级 | 推荐算法 | 理由 |
|----------|---------|------|
| 低噪声 (σ≤8) | **temporal_median3** | 计算量小，效果好 |
| 中噪声 (σ=8-15) | **avg3+median3+gauss** | 综合最优 |
| 高噪声 (σ>15) | **temporal5+adaptive_spatial** | 时域窗口大，空间自适应 |

### 5.2 对 Stage1 stat-based 的改进方向

1. **废弃纯幅值门限方法**：对于 64×64 膜片，改用时间+空间混合方法代替 baseline subtraction + gate
2. **保留 Analyzer 框架**：Analyzer 仍可用于估计噪声水平（σ），但 Processor 不再做 baseline subtraction，而是根据 σ 自适应调节空间/时域平滑强度

### 5.3 后续工作方向

1. **边缘保持**：探索引导滤波（guided filter）或双边滤波，在平滑噪声的同时保护压力边界
2. **自适应参数**：根据噪声水平自动选择滤波窗口大小和强度
3. **C++ 移植**：选定算法后移植到 `src/data/noise_suppressor.h/cpp`（v1.0.11 产品化）
4. **联合标定**：结合标定数据优化参数（目前使用的噪声水平为手工设定）

## 7. 问题陈述

Stage1 的三种算法在真实设备上有严重问题：

| 算法 | 问题 |
|------|------|
| **StatGate** | 硬门限切除过多信号，"损失太大" |
| **Spatial** | 高斯平滑使数据"团化"，失真严重，不忠实反馈真实结果 |
| **Hybrid** | 组合后感觉"完全是错误的" |

WebRTC NoiseSuppressor 教学文档（`NoiseSuppressor_Teaching_Document.md`）给出了正确的理论方向：
- 假设 `data = signal + white_noise`（加性白噪声模型）
- 通过统计方法估计噪声参数，然后用 **Wiener 滤波**（软增益）而非硬门限
- Decision-Directed 先验 SNR 平滑消除帧间抖动
- 分位数追踪噪声底噪（"追低不追高"）

**核心认识**：目前的 **glove 传感器**数据恰好符合这个加性白噪声假设——所有通道都有背景底噪（~8 ADC），
压力信号叠加在背景之上。这是音频 noise suppressor 算法的天然适用场景。

## 8. 新模拟数据设计

### 8.1 两阶段结构（关键设计变更）

不同于 Stage1 的模拟数据（所有帧都有压力信号 + ADC=0 背景），新数据采用 **两阶段结构**：

```
Phase 1: bg_frames (纯背景, 15 帧)
  x = per_channel_baseline + N(0, σ²)

Phase 2: sig_frames (压力信号, 15 帧)
  x = per_channel_baseline + pressure_blobs + N(0, σ²)
```

**Ground Truth**:
- Phase 1: gt = 0（全零）
- Phase 2: gt = pressure_blobs（压力图案）

**设计理由**：这模拟了真实工作流——先采集背景建模，再施压采集信号。

### 8.2 数据特征

- 每通道随机基线：μ = 12-20 ADC, spread = 4-8 ADC
- 加性白噪声：σ = 3-12 ADC
- 压力团块：高斯圆形 blobs，振幅 100-800 ADC
- 6 组数据集（单点、双点、五点掌压、大面积、边缘、弱信号高噪声）

### 8.3 关键区别

| 特性 | 旧数据 (synthetic/) | 新数据 (synthetic_blob/) |
|------|-------------------|------------------------|
| 背景基线 | ADC=0（膜片风格） | 5-50 ADC（手套风格） |
| 帧结构 | 全部含信号 | 前 N_bg 帧纯噪声 |
| 模型假设 | 无背景噪声 | 信号 + 白噪声 |
| 适用场景 | 64×64 膜片 | 手套/织物垫 |

## 9. WienerGate 算法设计

### 9.1 核心思想

从 WebRTC NoiseSuppressor 在频域的处理改为逐通道空域处理：

| WebRTC NS (频域) | WienerGate (空域) |
|---|---|
| FFT 分频 bin | 逐传感器通道 |
| 噪声谱 N(k) | baseline(c) + noise_std(c) |
| Post SNR: γ = \|X\|/N - 1 | γ = residual²/σ² - 1 |
| Prior SNR (DD): ξ = 0.98·ξ_prev + 0.02·γ | ξ = α·ξ_prev + (1-α)·γ |
| Wiener Gain: H = ξ/(α_os + ξ) | G = ξ/(α_os + ξ) |
| Output: Y = X · H | y = residual · G |

### 9.2 算法流程

```
[背景帧] → fit():
  1. baseline = median(bg_frames, axis=0)
  2. noise_std = std(bg_frames, axis=0), clamped to min 0.5
  3. prior_snr = [min_snr] * C  (初始化)

[信号帧] → process_frame():
  1. residual = max(frame - baseline, 0)
  2. post_snr = max(residual² / noise_std² - 1, 0)
  3. prior_snr = dd_alpha * prior_snr + (1-dd_alpha) * post_snr
  4. gain = prior_snr / (over_sub + prior_snr)
  5. output = residual * gain
```

### 9.3 与 StatGate 的关键区别

| | StatGate (Stage1) | WienerGate (beta2) |
|---|---|---|
| 门限类型 | **硬门限**: if r ≥ kσ keep else 0 | **软增益**: G ∈ [0, 1] 连续变化 |
| 边界行为 | 边缘通道被一刀切（零） | 边缘通道部分保留 (G ≈ 0.3-0.7) |
| SRR | 可能 >1（spatial 平滑放大） | 始终 ≤1（仅减不增） |
| 时间平滑 | 无（逐帧独立） | Decision-Directed α=0.98 |
| 信号保真 | 边缘损失严重 | 忠实反映输入比例 |

### 9.4 关键参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| k_sigma | 1.0 | 噪声底噪倍率（越小越激进） |
| over_sub | 1.0 | 过减因子（>1 增强抑制） |
| dd_alpha | 0.98 | 决策导向平滑（越接近 1 越平滑） |
| min_snr | 0.1 | 最小先验 SNR（防死寂） |

### 10.2 核心发现

#### 发现 1: 模拟数据上 StatGate/Hybrid CS 高于 WienerGate

原因：模拟数据信号/噪声分离**过于理想**。高斯压力团块边界清晰，白噪声完美独立，
压迫有信号区与无信号区的绝对分离。在这类数据上，硬门限"恰好"切在分界线上，
表现完美。Wiener 的软增益反而在此处画蛇添足。

**但这是数据特征问题，不是算法优劣问题。** 真实传感器的压力分布远非线性——有边界
渐变、弱接触、基底漂移——硬门限在这些场景下必然损失信号。

#### 发现 2: Hybrid 的 SRR > 1.0 暴露了根本性失真

在 `blob_weak_high_noise` 上，Hybrid 的 SRR = 1.2385，**意味着降噪后的信号比真实
信号还多 23.8%！** 这就是 spatial smoothing 导致的"团化"——高斯平滑将中心强信号
扩散到周围通道，制造了不存在的虚假信号。

这直接印证了用户对 Spatial/Hybrid 的批评：**"团化了很多真实值"**。

#### 发现 3: WienerGate 的 SRR 始终 ≤ 1.0

WienerGate 在所有数据集上 SRR ≤ 1.0：
- 正常信号: SRR = 0.95-0.98 (保守，有 2-5% 衰减)
- 弱信号: SRR = 0.735 (高噪声下 26% 的衰减换取 18.6dB BNSR)

**WienerGate 只衰减噪声，从不制造虚假信号。** 这是与 Spatial/Hybrid 的本质区别。

#### 发现 4: 2-5% 的 WienerGate 信号衰减来源

Wiener 增益 `G = ξ/(1+ξ)` 理论上永远 <1。对于 ξ >> 1 的强信号通道，G ≈ 0.99；
对于 ξ ≈ 1 的边缘通道，G ≈ 0.5。这导致整体平均保留率在 95-98%。

这个损失可以通过以下方式补偿：
- 降低 `dd_alpha`（加快先验 SNR 收敛）→ 让信号帧更快达到稳定增益
- 降低 `min_snr` → 防止过早起振
- 增加 `post_snr` 的敏感度（当前用 r²/σ² - 1，可以用 r²/σ²）

## 12. 结论与建议

### 12.1 算法评估结论

1. **StatGate 在理想数据上表现极好，但硬门限是其根本缺陷**——模拟数据证明了那
   种"一刀切"方式的脆弱性。用户在实际设备上观察到的"损失太大"正是硬门限在非理想
   信号/噪声边界上的必然表现。

2. **Spatial/Hybrid 的不忠定性被量化证实**——SRR > 1 是空间平滑"团化"的直接证据，
   这会导致假阳性加压检测（phantom contacts）。

3. **WienerGate 是唯一满足"忠实反馈"要求的方法**——SRR 从不超过 1.0，仅对噪声分量
   进行衰减。这匹配了 WebRTC NS 的软增益哲学：宁可保守也不制造虚假信号。

4. **软增益的 2-5% 信号损失是可以接受的**——相比硬门限的完全切除（实际设备上损失
   远超 5%）和空间平滑的虚假放大（最多 +24%），WienerGate 的保守策略是最可预测且
   最安全的。

### 12.2 对 C++ 产品化的指导

1. **废弃 Stage1 的 StatGate/Spatial/Hybrid 三模式设计**——改为单一 `WienerGate`

# beta2 补充 — 64×64 膜片的独立噪声模型
# ═══════════════════════════════════════════════════════════════

> 日期: 2026-07-11
> 触因: 用户观察到膜片噪声特征与手套/织物垫完全不同

## 13. 设备噪声特征分析

### 13.1 定量对比

```
                手套        织物垫       64×64 膜片
────────────────────────────────────────────────────
通道数           96          96          4096
bg_mean (全通道)  8.3        246.8        17.0
bg_mean 中位数    6.4         50.8         0.0  ← 一半通道完全无基线!
bg_mean < 0.5   0/96       1/96       3673/4096 (90%)
bg_std > 0.5    96/96      95/96       417/4096 (10%)
```

**手套/织物垫**: ALL 通道有基线 + 白噪声 → 符合 `x = baseline + signal + noise`
**64×64 膜片**: 90% 通道 ZERO，只有受压区 (~8%) 有值，噪声仅存在于受压边缘

### 13.2 膜片的噪声来源

```
不受压通道: x = 0                    (bg_mean=0.1, bg_std=0.03)
受压中心通道: x = pressure(t) ± 5-10  (信号本身帧间自然波动)
受压边缘通道: x = cross-talk_noise    (邻道串扰)
```

膜片的"噪声"实际上是：
1. 压力施加过程中的帧间幅值波动（不是传感器噪声，而是物理真实性）
2. 受力边缘的邻道串扰（cross-talk）

**这完全不符合 `signal + white_noise` 的加性噪声假设。**

WienerGate 为何在膜片上效果不佳：
- `baseline = median(bg)` 对所有通道计算 → 大多数通道 bg=0 → baseline≈0
- `noise_std = std(bg)` → 大多数通道 std=0 → clamped to 0.5 min
- 结果: baseline subtraction 几乎无效，gain 对所有非零通道都接近 1 → 等于没用

## 14. 膜片专用方案: MedianGate

### 14.1 设计动机

膜片数据的空间特征：
- 干净背景通道（值为 0）不需要任何处理
- 压力中心区域的边缘噪声是 **空间孤立的异常值** (salt-and-pepper at edges)
- 要求: 去除边缘异常值，同时保留清晰的边界和真实的压力幅值

**空间中值滤波 (Median Filter)** 是最佳选择：
- 不创造新值（仅从邻域选取）→ 不会"团化"
- 保留边缘（median 在边界处表现优异）→ 边界清晰
- 对孤立的 salt-and-pepper 异常值有效 → 去除串扰噪点
- 零值通道保持零值 → 背景干净

### 14.2 与 Gaussian 的对比

```
操作        Gaussian σ=1.5           Median 3×3
─────────────────────────────────────────────────
输出值      邻域加权平均（新值）        邻域中值（已存在值）
边缘行为    模糊/扩散/团化             保留锐利边界
零值邻域    会产生非零值                不会（median of [0,0,0,0,x] = 0）
团化程度    严重                        无（不创造新值）
```

### 14.3 对比结果

见 `output_membrane/membrane_*.png` 共 7 张图（1 真实 + 6 模拟）。

在真实膜片数据上：
- **Median 3×3**: 压力边缘噪点被清理，压力图案形态完整，非压力通道全零
- **Median 5×5**: 更大的去噪范围，但可能略微侵蚀压力边界（5×5 窗口覆盖太多通道）
- **Gaussian σ=1.5**: 明显的团化和模糊——这是之前的"团化"问题的直接画面证据

## 15. 双轨策略

根据设备类型分离降噪路径：

```
                      ┌─ 手套/织物垫 ──→ WienerGate ──→ 逐通道软增益
设备类型检测 ──┤      (96ch, 全局基线+白噪声)
                      │
                      └─ 64×64膜片 ──→ MedianGate ──→ 空间中值滤波
                         (4096ch, 零背景, 边缘噪声)
```

```
WienerGate                          MedianGate
─────────────────────────────       ────────────────────
模型: signal + white_noise          模型: 空间孤立噪点
方法: baseline_subtract + gain      方法: 3×3 median filter
要求: 背景帧（无压力）              要求: 无（不需要背景帧）
参数: k_sigma, dd_alpha, over_sub   参数: kernel_size=3
真实效果: 手套/织物上优秀            真实效果: 膜片上优秀
```

## 16. 结论更新

1. **WienerGate 对膜片不适用** —— 因为膜片没有全局白噪声底噪，Wiener 增益对所有
   非零通道（受压力通道）施加了不可区分的软衰减，既不必要也不正确。

2. **MedianGate 对膜片是最简方案** —— 3×3 中值滤波无基线依赖，无团化，无
   信号衰减（pass-through for clean channels）。

3. **两种噪声模型不可混淆** —— 手套/织物垫的加性白噪声和膜片的边缘串扰噪声是
   物理上完全不同的两个问题，无法用同一个算法解决。

4. **C++ 实现需分离** —— `Processor` 应支持 `Mode::WienerGate` (手套/织物)
   和 `Mode::MedianGate` (膜片) 两种模式。

## 17. 转折点

WienerGate 在模拟数据上优秀（逐通道 SNR 估计精准），但在真实 CSV 上无法复现。

用户指出：**"虽然不考虑 cell 之间的物理位置关系，但可能还是要将同时间在整个
layout 下的所有数据看成一个整体，进行成分分析。"**

这触发了从"逐通道独立处理"到"帧级整体分解"的范式转换。

## 18. Eureka: 压力信号的低秩性

### 18.1 实验验证

对三种设备去除基线后的矩阵做 SVD，计算累积能量：

```
手套 12×8  (去基线): s = [9.3, 5.4, 4.5, 3.5, 2.8, 1.8, 1.6, 0.7]
           累积能量: r1=53% r2=71% r3=82% r4=90% r5=95%
           有效秩 (90%能量) = 4

织物垫 12×8 (去基线): s = [197, 14, 8.7, 7.5, 3.6, 2.6, 1.6, 0.4]
           累积能量: r1=99.1% r2=99.6%
           有效秩 (90%能量) = 1

膜片 64×64 (直接): s = [3991, 1920, 1212, 1018, 898, 744, 641, 509, ...]
           累积能量: r1=64% r3=85% r5=92% r7=95%
           有效秩 (90%能量) = 7
```

**所有三种设备的有效秩都 << 满秩**（手套 4/8, 织物垫 1/8, 膜片 7/64）。
这意味着压力信号的绝大部分能量集中在极少量空间模式中，
而噪声均匀分布到所有模式。

### 18.2 物理意义

- **压力信号**: 物理接触形成的连续力分布 → 空间平滑 → 相邻通道强相关 → 低秩
- **噪声**: 电路热噪声/ADC量化/串扰 → 空间独立 → 各通道不相关 → 满秩
- **SVD 截断**: 保序 sigmas 中，大的捕获信号（空间相关），小的捕获噪声（空间无关）

这不需要任何噪声统计模型假设——**低秩 vs 满秩的分离是纯线性代数操作。**

## 19. SVD 降噪方案

### 19.1 算法

```
Frame M ∈ ℝ^{h×w}
U, Σ, Vᵀ = SVD(M)
r = rank with cumulative energy ≥ 90%
Σ' = diag(s₁,...,sᵣ, 0,...,0)
M_clean = U · Σ' · Vᵀ
```

对 12×8 手套/织物垫：先 `M_res = max(M - baseline, 0)`，再做 SVD
对 64×64 膜片：直接 SVD（背景基线 ≈ 0）

### 19.2 选秩策略

| 模式 | 方法 | 适用场景 |
|------|------|----------|
| `fixed` r=3 | 始终保留 3 个分量 | 已知极低秩 (织物垫) |
| `adaptive` | 保留到能量 ≥ 90% | **通用推荐** |
| `soft` | s' = max(s - τ·σ_med, 0) | 与硬阈值等效，数学上更优 |

### 19.3 对比结果

见 `output_final/final_*.png` 共 9 张图。

| 数据集 | 最佳算法 | 效果说明 |
|--------|----------|---------|
| 模拟数据 (6组) | SVD hard/adaptive | 与 Ground Truth 几乎一致 |
| 手套 1kg | **SVD adaptive** | 基线清除 + 压力区域完整保留 |
| 织物垫 500g | **SVD hard r=3** | 有效秩=1，几乎完美 |
| 膜片 1kg | **SVD adaptive** | 7 个空间模式 ~90%能量，远超 WienerGate |

## 20. 为什么 SVD 统一了所有设备

之前的双轨策略（WienerGate 手套 + MedianGate 膜片）基于一个错误假设：
手套/织物垫的噪声是"通道独立的白噪声"，膜片的噪声是"空间孤立的边缘噪点"。

**实际上，所有三种设备的噪声在空间上都是满秩的（空间无关或弱相关），
压力信号在空间上都是低秩的（空间平滑）。** 这是一个对两种噪声来源都成立的
物理约束——它不依赖于噪声是白的（手套）还是稀疏的（膜片），只依赖于
压力是物理接触=空间连续的。

所以 SVD 是**单一算法适配所有设备**，不需要切换。

## 22. 为什么 SVD hard 还不够

SVD hard 的价值在于它已经从“逐通道处理”跨到了“整帧处理”，但它仍有局限：

1. **只看单帧**
   - 它不知道整段真实记录的主要压力模式是什么
   - 只能在当前这一个矩阵里硬截断

2. **是硬截断，不是软收缩**
   - 小奇异值直接砍掉
   - 对边界弱成分仍然过于粗暴

3. **隐含的是 2D 矩阵低秩，而不是整帧向量子空间**
   - 用户要的是“同一时刻整个 layout 作为整体”
   - 更合适的是多帧共同学习一个 layout-level 子空间

## 23. 新方向: PCA 子空间降噪

新原型实现：

- `scripts/pca_subspace_denoiser.py`
- `scripts/render_pca_comparison.py`
- 输出目录: `output_pca/`

算法核心：

```
每帧 x_t ∈ R^C
整段数据 X ∈ R^(T×C)

1. 学习 baseline / noise_std
2. 做 whitening
3. 在 X 上做 PCA / SVD，得到主子空间 V_k
4. 单帧投影 coeff = V_k x
5. 在 coeff 上做软收缩
6. 回投影 x_hat = V_k^T coeff_shrunk
```

1. **PCA 子空间降噪** ← 新主线

## 25. 为什么尝试 NMF

在 PCA 路线之后，下一步选择了 NMF（Non-negative Matrix Factorization），原因：

1. **整帧整体建模**：每帧作为一个高维向量，满足“整体 layout 分析”要求
2. **时序建模**：NMF 用整段帧序列 `X ∈ R^(T×C)` 拟合 `X ≈ W @ H`
3. **非负约束**：压力值天然非负，比 PCA 的正负振荡基更符合物理意义
4. **小噪声前提**：用户已明确当前先不考虑大规模白噪声，NMF 的主模式分解适合小扰动场景

- `glove_like_12x8`
- `membrane_small_12x8`
- `membrane_mid_32x16`
- `membrane_large_64x64`

特点：
- 含时序 profile（缓慢升降）
- 噪声强度较小
- 同时覆盖 glove-like 与 membrane-like 两类噪声结构

## 27. 初步结果

### 当前判断

1. **NMF 路线在物理意义上是合理的**
   - 整体 layout
   - 时序建模
   - 非负约束

2. **但当前这版实现没有形成突破**
   - glove_like 上甚至更差
   - membrane-like 上与 PCA 几乎没有区别

   - 说明问题不在“是否用了时序”，而在于当前重建/收缩方式本身仍然过于削弱主信号

## 28. 本轮结论

本轮研究的价值不在于“找到了新算法”，而在于进一步排除方向：

- 不只是 Wiener 不对
- 不只是单帧 SVD 不够
- **连简单 NMF 时序重建也还不够**

因此下一步若继续研究“整体 + 时序”，必须进入更细的模型：

1. 主成分重建
2. 残差单独建模
3. 支持域约束
4. 可能还需要把“背景、主模式、局部细节”三项显式拆开

# beta2 — EdgeGate 空间结构感知边缘筛选
# ===============================================================

> 日期: 2026-07-11
> 触因: 用户建议尝试类似图像边缘检测 + 筛选的方法

## 29. 为什么转向 EdgeGate

用户提出关键思路转换:

  "这个问题看上去更像是图像的锐化，做的其实有点类似边缘检测的工作，
  然后将被筛选掉的部分就认为是白噪音。"

这触发了从"统计降噪重建"到"空间结构感知筛选"的范式转换。

之前的 Wiener/PCA/NMF 都是"把噪声压下去"（衰减/压缩），
EdgeGate 是"把信号挑出来，其余归零"。

## 30. EdgeGate 实现

新脚本: `scripts/edge_gate.py`

算法:
1. 计算局部均值 + 局部方差（3x3 窗口）
2. 方差高 + 均值高 -> 边缘 -> 保留
3. 方差低 + 均值高 -> 压力内部 -> 保留
4. 方差低 + 均值低 -> 噪声 -> 归零
5. 形态学闭运算 + 去除小连通域
6. 输出 = 原值 x mask（不衰减）

## 31. 初步结果（模拟数据）

| 数据集 | SRR | 对比 PCA | 对比 NMF |
|--------|-----|---------|---------|
| membrane_large_64x64 | 0.973 | 0.611 | 0.610 |
| membrane_mid_32x16 | 0.895 | 0.615 | 0.613 |
| membrane_small_12x8 | 0.701 | 0.605 | 0.603 |
| glove_like_12x8 | 0.459 | 0.664 | 0.578 |

## 32. 突破性发现

**EdgeGate 在膜片场景下形成了显著突破:**

- 64x64 SRR 从 0.61 跃升到 0.97 (+59%)
- 32x16 SRR 从 0.61 跃升到 0.90 (+46%)

这证明了两个重要事实:

1. 筛选比重建更适合触觉传感器 - 压力信号有清晰空间边界，直接筛选比整体重建保留了更多真能量。

2. 之前 PCA/NMF 失败的主因不是"用了整体分析"，而是"重建过程压缩了不该压缩的边缘/细节" - EdgeGate 的筛选不压缩原值，只归零噪声区。

## 33. 手套场景仍需改进

glove_like_12x8 上 SRR=0.459（不如 PCA 的 0.664），原因是:
- 手套所有通道都有基线噪声 (~8 ADC)
- 局部分类在低对比度区域（信号 20-35 vs 基线 ~8）上难以区分
- 需要引入背景帧学到的 noise_std 作为自适应门限

## 34. 对后续的建议

1. 膜片路线已经可以用 EdgeGate 作为 baseline - 64x64 SRR=0.97 是可信的
2. 手套路线需要单独攻克 - 方向是自适应阈值结合 noise_std
3. 时序信息可能帮助手套 - 偶发闪点 vs 稳定存在多帧的信号
