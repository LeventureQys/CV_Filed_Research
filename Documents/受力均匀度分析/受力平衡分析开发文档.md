# 受力平衡分析改造开发文档

> 文档目的：指导后续把 v2.2.2 的受力平衡分析，从“能计算并画出若干标记”的雏形，改造成“数据口径一致、边界可信、用户看得懂”的 2D 辅助工具。
>
> 本文是实施计划和工程契约，不是验收报告。本轮只更新文档和配图，没有修改 C++ 代码。算法目标说明见同目录 `受力平衡分析算法说明.md`；两份文档必须一起阅读。

## 1. 目标、范围与完成定义

### 1.1 产品目标

功能只服务于一个场景：用户用压头接触传感器时，软件帮助他判断当前施力是“位置偏了”，还是“可能压歪了”。最终输出必须能直接转成动作：

- 位置偏移：给出“当前受力中心 → 目标中心”的单头箭头，建议微调方向。
- 形状异常：给出“某侧压力偏大，可能压头倾斜”的提示，建议检查贴合，不给第二个推动方向。
- 可信度不足：提示减小压力、扩大接触或等待有效数据，不把不可靠结果包装成 PASS。

### 1.2 明确不做的事情

- 不把功能注册为测试工作台步骤，不进入 TRG/MIN/ACC 流程、NG 报告或测试结果库。
- 不判断传感器制造均匀性、坏点质量或标定曲线是否正确。
- 不反演压头精确倾角、扭矩、几何形状或机械位移。
- 不在 ADC/换算链路饱和后插值、外推或伪造真实压力。
- 不承诺在 3D、波形或其他非 `PixmapWidget` 2D 视图中提供同样的分析 overlay；本阶段只做 2D。

### 1.3 完成定义

只有同时满足以下条件，才可称为本轮改造完成：

1. 分析输入、进入阈值、权重、单位和量程上限具有明确且一致的契约。
2. 无效布局点、NaN、负值和异常尺寸不会污染结果。
3. 斑块边界按真实 Cell 边缘绘制，不能用外接矩形代替。
4. 多斑块跨帧有稳定身份，EMA 不会把一个区域的历史中心套到另一个区域。
5. 位置偏移、倾斜风险、饱和风险三种状态不会互相发出矛盾文案。
6. 单元测试、数据链路测试、overlay 视觉检查和真实压头试验分别通过。
7. 文档中的“能判断/不能判断”与界面实际文字一致。

### 2.2 现状与需求的关键差异

1. **矩阵名称与真实含义不一致**：`PixmapWidget::raw_data_double_` 在主数据路径中接收的是已经经过显示单位处理、显示阈值过滤、布局重排和坐标变换的矩阵，不是设备刚上报的原始 ADC。后续必须改名或拆成明确的 `analysis_values`、`display_values`、`raw_adc`。
2. **阈值和权重可能混用口径**：进入阈值按当前模式读取，但必须确认传入分析器的每个值也在同一模式和单位。不能出现“阈值是压强、权重仍是 ADC”的组合。
3. **有效布局掩码没有进入分析器**：`PixmapWidget` 有 `valid_data_mask_`，但当前 `AnalyzeForceBalance` 只看数值和阈值；无效点若带有非零数据会被错误并入斑块。
4. **饱和上限取错层级**：当前调用使用 `adc_max_show_value`、`force_max_show_value` 或 `pressure_max_show_value`。这些是颜色显示上限，不自动等于硬件/测量链路量程上限；必须单独提供 `hardware_ceiling`。
5. **边缘红线实际上是外接矩形**：`DrawBalanceOverlay` 以最小/最大行列调用 `drawRect`，会把 L 形、凹形和空洞外部标成受力区域，不能满足真实连通斑块要求。
6. **二阶面积配置没有真正生效**：头文件提供 `second_order_min_cells`，实现却直接用 `n < 9`；必须统一配置来源并校验范围。
7. **EMA 按排序下标配对**：当前斑块按面积排序后用数组下标复用历史中心；合并、分裂或面积交换时会错配。只看斑块数量是否变化不够。
8. **状态可能互相矛盾**：位置偏差在合格圈内时可以显示“已平衡”，同时又显示二阶异常或饱和提示；目标状态必须有明确优先级。
9. **异常值清洗不完整**：热力图绘制路径对非有限值有处理，但分析器可能直接接收到 NaN 或负值，导致求和和重心传播异常。
10. **当前 8 邻接未与“实心连通”语义确认**：Cell 仅在角点接触时是否应算同一区域，必须由产品和实测样本确定。默认建议四邻接，八邻接作为可选兼容模式。

这些差异在编码前必须登记为待修项，不能通过继续调整颜色或阈值掩盖。

## 3. 目标数据契约与算法接口

### 3.1 推荐的帧输入

不要让算法器从 `PixmapWidget` 的成员变量猜测数据含义，建议建立一个明确的输入对象（实际命名可按项目风格调整）：

```cpp
struct BalanceFrameInput {
    Eigen::MatrixXd values;       // 当前显示单位，颜色裁剪前
    Eigen::Matrix<uint8_t, Eigen::Dynamic, Eigen::Dynamic> valid_mask;
    QString display_mode;          // adc / pressure / force
    QString unit;                  // 与 values 一致
    double enter_threshold = 0.0;  // 与 values 同单位
    double hardware_ceiling = 0.0; // 未知时为 0，禁止猜测
    qint64 timestamp_us = 0;
    QVector<QPointF> cell_centers; // 可选；无布局时使用 row/col
};
```

实际项目也可以把模式、单位和参数放入 `BalanceAnalyzeConfig`，但必须保证下面的语义不变：

- `values` 已完成同一帧的布局映射、旋转/镜像和显示单位换算。
- `values` 尚未经过颜色 LUT 的 0～255 裁剪；显示色阶只影响颜色，不改变分析数字。
- 进入阈值 `T` 与 `values` 同单位，明确使用 `value > T`。
- `valid_mask=false` 的 Cell 永远不能进入连通域、重心、颜色统计或饱和比例。
- 只接受有限、非负值；NaN/Inf 和不允许的负值在域层统一排除并记录质量标志。
- `hardware_ceiling` 代表硬件或可靠换算链路的真实上限，不得用颜色条最大值代替。
- `cell_centers` 若存在，应使用每个 Cell 的实际物理中心；没有布局时才回退到规则 row/col 坐标。

### 3.2 数据链路改造顺序

当前主路径大致是：

```text
DataHandler 换算 → 显示阈值过滤 → 布局/坐标变换 → CentralWidget → PixmapWidget::SetData
```

目标路径应改为：

```text
设备/回放数据
  ├─ 原始 ADC（仅用于诊断和硬件饱和判断）
  └─ 当前显示模式的未裁剪矩阵 + valid_mask + 几何元数据
        ├─ 颜色归一化/渲染
        └─ BalanceAnalyzer
```

推荐做法是扩展 `SetData` 或 `AppCentralWidget::UpdateDisplay` 的数据载荷，一次传入分析需要的矩阵和元数据；不要在 `PixmapWidget` 内部再次猜测或重复换算。若短期无法改变信号类型，至少先把“阈值过滤前的显示单位矩阵”单独缓存，并明确哪个矩阵用于热力图、哪个用于分析。

注意：如果产品坚持分析只使用阈值后的矩阵，则必须把这一点写入契约，并接受边缘信息已经丢失；不能一边使用阈值后矩阵，一边在文档声称“颜色裁剪前原始数据”。

### 3.3 推荐的分析结果

结果对象应同时携带数值和可信度，而不是只返回几个坐标：

```cpp
struct BalanceBlobResult {
    int stable_id = -1;
    QVector<QPoint> cells;
    QVector<BoundaryEdge> boundary_edges;

    QPointF reference_center;
    QPointF current_center;
    QPointF offset;
    ReferenceSource reference_source;

    double total_value = 0.0;
    double mean_value = 0.0;
    double saturated_fraction = 0.0;

    bool second_order_valid = false;
    bool tilt_warning = false;
    bool heavy_side_valid = false;
    QPointF heavy_side_direction;

    BalanceConfidence confidence = BalanceConfidence::Normal;
    QStringList quality_flags;
};
```

字段名可以不完全照抄，但至少要能区分：

- 参考中心和当前中心；
- 参考中心的来源（已知目标、稳定掩码、临时核心）；
- 二阶分析是否执行，而不是把“未执行”当作“正常”；
- 偏重方向是否有效；
- 饱和、无效数据、面积不足和拓扑变化等质量状态。

## 4. 分阶段实施方案

### 阶段 A：先稳定纯算法域层

**目标**：不碰 UI，先让相同输入总能得到可解释、可复现的结果。

1. 将连通域提取、边界生成、位置中心、形状异常、饱和统计拆成独立的纯函数或小组件。
2. 增加 `valid_mask`、有限值和负值处理；所有异常输入返回明确质量标志，不传播 NaN。
3. 固定连通语义。建议默认四邻接；如果保留八邻接，必须把它作为显式配置，并增加“角点连接”测试和产品说明。
4. 使用配置中的 `second_order_min_cells`，删除硬编码 9；保留默认 9 作为初始值。
5. 真实边界按 Cell 四条边生成：某条边外侧越界、无效或不属于当前 blob 时绘制；相邻 Cell 的共享边只绘制一次。结果返回边段给 UI，不返回外接矩形作为唯一轮廓。
6. 斑块超过最大数量时返回 `detected_blob_count`、`analyzed_blob_count` 和 `truncated=true`，按面积取前 N 个只是显示策略，不能静默丢失信息。
7. 重新定义参考中心：
   - 有已知目标几何时优先使用目标中心；
   - 否则在接触掩码连续稳定若干帧后冻结其几何中心；
   - 初始帧可用峰值核心中心，但标记为临时参考。
8. 一阶当前中心仍按同口径正值加权；二阶形状分析可继续使用 95 分位截断，但不要把截断后的权重悄悄当成物理总力。
9. 二阶结果的方向表达分两层输出：
    - **轴向命名**（始终输出）：由主失衡轴两端方位名生成（如“左上—右下”），这是 λ 方向信息的本体——λ 给出的是双向轴，不是单向指向；
    - **偏重侧**（差异显著才输出）：两侧每 Cell 均值之差超过显著阈值（相对均值的比例，如 10%）时输出 `heavy_side_valid=true` 与方向向量，用于铺色和“X侧偏重”文案；两侧相当（重压集中在轴线上）时输出“轴向集中”状态；两侧为空、均值相等或轴退化时 `heavy_side_valid=false`，禁止输出确定方位，也禁止“中心侧”这类无意义方位；
    - **程度分级**：λ 映射为“轻度/明显”两档字段供 UI 使用，精确数值只进详情面板。
10. 将“位置偏差达标”“倾斜风险”“量程风险”分别计算，最后由状态组合器决定界面状态。

**阶段 A 交付物**：域层接口、边界边段、结果质量字段、纯算法单测和固定矩阵夹具。

### 阶段 B：修正数据管线和单位口径

**目标**：确保用户看到的数字与算法使用的数字不会分叉。

1. 在 `DataHandler` 的换算和坐标变换完成后，保留一份未颜色裁剪的当前显示单位矩阵。
2. 将有效布局掩码随矩阵传递；无布局规则网格也要生成全有效或明确缺失的掩码。
3. 为 ADC、力值、压强分别提供进入阈值；切换模式时只切换对应配置，不在分析器内部隐式换算。
4. 分离三个概念：
   - 显示色阶上限：只用于颜色；
   - 显示数值单位：用于阈值和一阶权重；
   - 硬件/测量量程上限：仅用于可信度和饱和检测。
5. 若力值或压强没有可靠的物理上限，`hardware_ceiling=0` 并关闭饱和提示；不能使用 `force_max_show_value` 等 UI 色阶值猜测。
6. 旋转、镜像、布局映射必须在分析前完成，方向文案按屏幕坐标统一：行向下、列向右。
7. 给分析帧附带时间戳或序号，供后续区域跟踪和性能统计使用。

**阶段 B 交付物**：明确的帧输入对象或扩展信号、三模式口径测试、布局掩码测试、硬件量程配置。

### 阶段 C：增加斑块身份和时间稳定

**目标**：实时画面稳定，但不把不同区域的历史混在一起。

1. 域结果先按面积排序只是展示排序，不能作为身份。
2. 为每个活动斑块分配 `stable_id`。相邻帧优先按 Cell 交集比例匹配，辅以中心距离和边界重叠；一个旧斑块不能匹配两个新斑块。
3. 新斑块先进入候选状态，连续达到确认帧数后才显示完整结论；消失斑块保留短暂的离场滞后，避免闪烁。
4. 只有匹配成功的斑块才复用 EMA。匹配失败、合并、分裂、跨越大距离或掩码大幅改变时重新初始化。
5. EMA 只平滑中心点；二阶异常和饱和建议采用短时确认/消抖，不要把严重异常延迟太久。
6. 设置变化、显示模式切换、布局切换、开关关闭和数据尺寸变化时清空相关轨迹状态。
7. UI 中若有多个区域，显示 `区域 1/区域 2` 或稳定 ID，使文字和边界能对应起来。

**阶段 C 交付物**：`balance_blob_tracker`（可放在域层或 UI 业务层）、拓扑变化单测、连续帧仿真夹具。

### 阶段 D：重做 overlay 的信息层级

**目标**：默认画面让非专业用户一眼知道“该怎么做”。

1. 按以下顺序绘制：真实边界 → 相对偏重/偏轻色块（仅在需要时）→ 目标/当前标记 → 单头位置箭头 → 倾斜风险色带/轴线 → 可信度提示。
2. 真实边界直接使用阶段 A 的 `boundary_edges`，删除 `drawRect(outline)` 作为斑块边界的做法。
3. 只保留两类动作语言：
   - 单头箭头：向箭头方向微调压头；
   - 倾斜提示：停止平移，检查压头是否贴平。
4. 不绘制会被理解为动作指令的倾斜“双头箭头”；紫色虚线轴只表示失衡方向轴线。**轴向必须配命名文案**（“沿左上—右下方向失衡”），否则双向轴本身看不出哪侧异常；偏重侧铺色只在 `heavy_side_valid=true` 时出现，且透明度要足以一眼分辨（当前 alpha 55 偏弱，建议实测调高）。
5. 每个斑块显示简短状态，不把所有指标堆在图内。建议默认只显示：
   - `受力中心已对齐`；
   - `请向左上方微调`；
   - `压力沿左上—右下方向失衡，左上侧偏重，可能压头倾斜`（轴向 + 偏重侧）；
   - `压力沿左上—右下方向集中，可能压头倾斜`（轴向集中、两侧相当）；
   - `压力分布失衡（方向不确定），请检查压头贴合`（方向退化）；
   - `读数可能不可靠`。
   失衡程度以“轻度/明显”后缀词或详情面板呈现，不在主画面显示百分比或 λ 数值。
6. 高级数值（偏差、面积、总力、二阶强度、饱和比例）放到可展开的详情面板或 tooltip，不作为主画面唯一文案。
7. 增加固定小图例，说明“目标/当前/箭头/偏重/倾斜提示”的含义；多斑块文字要做边界裁剪和碰撞避让。
8. 状态组合必须遵守优先级：无数据 → 可信度不足 → 倾斜风险 → 位置偏移 → 位置对齐。饱和或倾斜存在时禁止显示无条件的“已平衡”。
9. 对面积不足的区域显示“受力中心已对齐（未检查倾斜）”或等价文案，不能显示“倾斜正常”。
10. 当分析区域超过最大显示数量时，在视图顶部或信息面板提示“检测到 X 个区域，当前显示 Y 个”。
11. `ComputeBalanceBlobs` 不应只依赖 overlay cache 偶然重建；数据、参数、显示模式、布局和开关变化都要明确使分析缓存失效并触发刷新。

**阶段 D 交付物**：overlay 重构、图例/详情面板、文字布局测试和人工截图验收。

### 阶段 E：设置、持久化和入口收口

**目标**：参数可理解、可恢复、作用域明确。

1. 保留现有 menubar action 和非模态 `QPointer` 管理范式，不新建第二套窗口生命周期。
2. 设置对话框分为“常用”和“高级”：
   - 常用：三模式进入阈值、最小区域 Cell 数、位置允许偏差、最大显示区域数；
   - 高级：连通规则、参考中心方式/核心比例、二阶最小面积、倾斜阈值、饱和比例、平滑帧数、硬件量程。
3. 每个输入框附带一句影响说明；例如“阈值过低可能把噪声算入区域”“平滑帧数越大响应越慢”。
4. 单位随当前视图切换：没有有效布局时显示 Cell；有有效物理坐标时显示 mm。位置允许偏差也必须与当前单位一致，不能只改标签不改计算。
5. 既有键可以兼容读取，但应建立迁移规则：
   - `balance_peak_reference_fraction` 作为临时核心参考的旧参数保留；
   - `balance_ok_radius_cells` 迁移为明确的“位置允许偏差”，旧值按 Cell 解读；
   - 新增 `balance_reference_mode`、`balance_connectivity`、`balance_second_order_min_cells`、`balance_hardware_ceiling_*` 等键时提供默认值和版本号。
6. 参数持久化与运行时状态分开：阈值、显示偏差和算法参数写入 `UserSettings`；右键开关默认按窗口会话管理，若要跨重启记忆必须新增明确的持久化键并在 UI 说明。
7. `UserSettings` 是持久化唯一入口，`AppState` 只保存当前运行快照；设置保存后通过统一信号触发分析重算，不让控件直接修改多个地方。
8. 恢复默认值时同步清空跟踪、EMA 和结果缓存，避免旧状态短暂残留。

**阶段 E 交付物**：设置键清单、迁移测试、对话框交互和模式切换测试。

## 5. 测试与验收计划

### 5.1 域层单元测试

在 `tests/app/test_force_balance_analyzer.cpp` 或拆分出的新测试目标中覆盖：

| 类别 | 必须验证 |
|---|---|
| 输入 | 空矩阵、尺寸不一致、全零、NaN、Inf、负值、零总权重 |
| 掩码 | 无效 Cell 不入域、不参与中心、边界和饱和比例 |
| 连通 | 阈值严格边界、四/八邻接差异、角点连接、孔洞和 L 形区域 |
| 过滤 | 最小 Cell 数、最大区域数、截断计数和面积排序 |
| 一阶 | 均匀区域中心重合；单侧偏重箭头方向正确；整体等比放大中心不漂移 |
| 参考中心 | 已知目标、稳定掩码、临时核心三种来源；边缘扩张不拖动稳定参考 |
| 二阶 | 对角失衡可检出；均匀对照接近零；面积不足标记未执行；轴向命名两端方位正确；轴向集中（重压在轴线上）时输出“集中”而非偏重侧；两侧均值差异显著/不显著两 case 的 heavy_side_valid 正确；主轴退化不输出偏重方位 |
| 稳健性 | 95 分位截断抑制单点毛刺，但不影响一阶字段语义 |
| 饱和 | 硬件上限已知时比例正确；显示色阶改变不改变饱和结果；上限未知时关闭 |
| 坐标 | 行向下/列向右、旋转镜像后的方向与屏幕一致 |

每个测试应同时断言“数值”和“状态字段”，不能只断言 `dev_strength > 某值`。

### 5.2 连续帧和数据链路测试

新增或扩展测试覆盖：

1. ADC、力值、压强三种模式的阈值、单位和权重同源。
2. 改变颜色条上限不会改变位置中心、区域成员和倾斜结论。
3. 布局无效点即使有非零输入也不会形成斑块。
4. 区域面积排序变化不会交换稳定 ID。
5. 区域合并、分裂、消失和重新出现时 EMA 正确重置或恢复。
6. 参数修改、模式切换、布局切换和关闭开关会触发重算，不残留旧 overlay。
7. 回放、仿真和无设备矩阵都可以走同一分析入口，不依赖连接状态。

### 5.3 Overlay 视觉测试

至少准备以下固定矩阵和截图：

- 规则矩形：验证中心、箭头和合格圈。
- L 形：验证真实边界，不出现矩形补全。
- 带孔区域：验证孔洞不被圈入。
- 两个独立区域：验证边界、标记和文字不串区。
- `6|4 / 4|6` 或等价 3×3 对角样本：验证箭头为零时仍提示倾斜风险，文案含轴向命名，且对角集中样本不出现“某侧偏重”。
- 小于二阶最小面积：验证显示“未检查倾斜”，不显示“倾斜正常”。
- 饱和样本：验证可信度提示和状态优先级。
- 高 DPI、缩放、平移、窄窗口：验证文字不越界、不遮住中心标记。

如果没有现成的 QPainter 像素级测试，至少建立可重复的截图夹具和人工检查表；不要只依赖算法单测宣称 UI 正确。

### 5.4 真实压头验收

算法数值通过不等于用户能正确操作。使用至少一套正常压头和一套可重复制造偏差的压头，按下面步骤记录：

1. 正常平压：应显示受力中心对齐，无倾斜风险。
2. 整体向左/右/上/下偏移：箭头方向应与预期相反地指向修正方向。
3. 对角加压或压头翘曲：箭头可能接近零，但应出现“可能压头倾斜”，不能显示无条件平衡。
4. 两个独立接触区域：用户能分别识别并调整，不把两个区域当成一个总中心。
5. 逐渐增加压力：参考中心不应因边缘 Cell 逐个过阈值而明显漂移。
6. 接近量程上限：出现降低压力提示，且不再声称结果完全可靠。
7. 观察区域合并/分裂：箭头不会跳到另一个区域，提示不会串区。

记录误报、漏报、响应延迟、用户是否理解文案和调整后是否真的改善；“能否指导用户”必须由这组实测确认。

### 5.5 性能验收

记录不同矩阵规模和帧率下的：

- 连通域与分析耗时；
- overlay 绘制耗时；
- P95/P99 帧处理耗时；
- 高频数据更新时 GUI 是否卡顿或堆积。

目标是保持线性复杂度，不引入迭代优化或物理反演。性能测试应使用真实发布配置和代表性矩阵，不能只测空矩阵。

### 5.6 推荐构建与测试顺序

遵守项目按业务套件和增量构建策略：

```powershell
# 先检查是否已有可复用的 build-tests-* 目录，再决定套件树
Get-ChildItem -Directory -Filter 'build-tests-*'

# 若改动域算法/2D渲染，使用已有 render 套件树；首次建树才新建同名套件树
cmake -S . -B build-tests-render `
  -DBUILD_TESTS=ON `
  -DTACTILE_TEST_SUITES=render `
  -DBUILD_BENCHMARKS=OFF `
  -DBUILD_CALIBRATION_FLOW_PROTOTYPE=OFF `
  -DBUILD_PORTABLE_TOOLS=OFF

cmake --build build-tests-render --config Release `
  --target test_force_balance_analyzer -- /m:4

ctest --test-dir build-tests-render -C Release `
  -R '^test_force_balance_analyzer\.' --output-on-failure
```

若新增 UI 专项测试，按实际目标加入 `ui` 套件或与 render 组合选择；不要默认打开全量测试，也不要删除可复用的测试树制造全量编译。

## 6. 兼容、回滚与风险控制

### 6.1 参数兼容

- 旧版设置文件缺少新键时使用集中默认值，不因读取失败关闭主程序。
- 旧版 `balance_ok_radius_cells` 等键先兼容读取，写回时可升级到新 schema；迁移必须有单测。
- 不恢复已删除的 UNI 测试项、旧模板兼容或 NG 链路；受力平衡仍是独立视觉工具。

### 6.2 关键风险及应对

| 风险 | 应对 |
|---|---|
| 没有压头几何，目标中心物理含义不足 | 使用“参考中心/临时参考”术语，并显示来源或降低结论等级 |
| 显示矩阵与原始 ADC 口径混杂 | 在数据对象中同时标注 domain/unit/ceiling，禁止裸 `Eigen::MatrixXd` 跨层传递 |
| 4/8 邻接改变区域数量 | 用真实样本定规则，配置和文档同步，不在 UI 中默默改变 |
| 高速帧导致 GUI 重绘堆积 | 保留最新帧、合并失效通知，测量 P95/P99；分析不放到阻塞 UI 的长任务中 |
| 二阶误报被用户当成移动方向 | 倾斜只用颜色/自然语言提示，不画第二个动作箭头 |
| 多斑块文字遮挡 | 稳定 ID、标签锚点、碰撞避让和顶部汇总提示 |
| 饱和阈值未知 | 关闭饱和结论并明确“未配置量程”，绝不使用颜色上限猜测 |

### 6.3 分阶段回滚

每个阶段应保持可编译、可测试：

- 阶段 A 回滚只影响域层接口，可暂时保留旧 overlay 调用适配器；
- 阶段 B 回滚时保留旧 `SetData` 重载，但不得同时启用两套不同单位的分析；
- 阶段 C 回滚可关闭 EMA/稳定 ID，回退为逐帧结果，但必须明确这是降级模式；
- 阶段 D 回滚只能回退视觉样式，不能恢复外接矩形边界或矛盾状态文案；
- 阶段 E 回滚设置时保留旧键读取，避免用户设置文件失效。
