# 从世界到像素：聊聊图像采样与量化

> 写给正在入门 CV 的你

## 写在前面

想象你站在窗前，望着外面的景色。光线连绵不绝地涌入你的眼睛，每一处的明暗、每一种颜色，都在空间和强度上**连续**地变化着——树叶的边缘没有"格子"，蓝天和云彩的交界也不是某条精确的线。

可问题来了：计算机不会"看"连续的世界。它只懂数字——而且是**有限**的数字。

那么，我们怎么把那扇窗外的真实风景，搬进硬盘里？

这就是这篇文章的主角：**采样**（sampling）把世界切成网格，**量化**（quantization）把每个网格里的值压成有限的数。两件事一做，世界就被"翻译"成了一张数字图像。

我们一点点来。

---

## 第一部分：图像采样

### 1.1 什么是图像采样

打个比方：你想把一片真实的草地"拷贝"下来，做法是在草地上铺一张**渔网**，每个网眼对准一个位置，记下那个位置上草的颜色。网眼越密，记得越细；网眼越稀，记得越粗糙。

**这就是采样**：在连续的空间里，按一定间隔选取离散的点。

数学上，假设真实世界的图像是一个二维连续函数：

$$
f(x, y), \quad (x, y) \in \mathbb{R}^2
$$

它在每个位置 $(x, y)$ 都有一个亮度（或颜色）值。采样就是用一个**二维冲激串**（dirac comb，也叫梳状函数）去"叮"它：

$$
f_s(x, y) = f(x, y) \cdot \sum_{m=-\infty}^{\infty}\sum_{n=-\infty}^{\infty} \delta(x - m\Delta x,\; y - n\Delta y)
$$

其中 $\Delta x, \Delta y$ 就是采样间隔。结果 $f_s$ 是一组离散位置上的数值——这些点，就是我们熟悉的**像素**（pixel，picture element 的缩写）。

```
连续世界 f(x,y)                  采样后 f[m,n]
┌──────────────────┐             ┌─┬─┬─┬─┬─┬─┐
│   ░░▒▒▓▓██▓▓     │             │░│▒│▓│█│▓│▒│
│   ░▒▓▓██████▓    │   采样       ├─┼─┼─┼─┼─┼─┤
│   ▒▓████████▓    │   ────►     │▒│▓│█│█│█│▓│
│   ░▒▓▓████▓▒     │             ├─┼─┼─┼─┼─┼─┤
│   ░░▒▒▓▓▒░       │             │░│▒│▓│▓│▒│░│
└──────────────────┘             └─┴─┴─┴─┴─┴─┘
   光滑、连续                       离散、有格子
```

> 💡 **像素不是小方块**。这是个常见误解。像素其实是空间中某个**点**上的采样值；我们在屏幕上看到的"方块"，只是显示设备的渲染方式而已。这一点等会儿讲"图像重建"时还会回来。

### 1.2 采样定理：到底要多密才够？

铺渔网这事儿，关键问题是：**多大的网眼合适？**

凭直觉，网眼越细越好，细到无穷小就完美还原了真实世界。可现实里，网眼越细意味着像素越多，存储和计算成本都涨。

那有没有一个"够用"的下限？

有，而且这是信号处理里最优雅的定理之一——**奈奎斯特-香农采样定理**（Nyquist-Shannon sampling theorem）：

> 若信号 $f$ 的最高频率不超过 $f_{\max}$，则采样频率 $f_s$ 必须满足
> $$f_s \geq 2 f_{\max}$$
> 才能从采样点完美重建原信号。

这个 $2 f_{\max}$ 就是大名鼎鼎的 **奈奎斯特频率**。

#### 直观一点：频率到底是什么

在图像里，"频率"指的是**空间上亮度变化的快慢**：

- **低频**：大片均匀的天空、墙面——亮度变化慢
- **高频**：头发的细丝、织物的纹理、文字的边缘——亮度变化快

```
低频 (变化慢)                    高频 (变化快)
─────────╱╲─────                ╱╲╱╲╱╲╱╲╱╲╱╲
   一片天空                       密集的栅格
```

如果一片细密的栅格每毫米有 10 道黑白条纹（$f_{\max} = 10$ 条/mm），那你的采样率至少要每毫米取 20 个点，才能把这些条纹忠实地记录下来。

#### 不够密会怎样：混叠（Aliasing）

如果采样率**不够**，就会出现一个迷人但麻烦的现象——**混叠**。

举个生活里的例子：电影里旋转的车轮，明明在向前开，看起来却像在**倒转**。这不是车有问题，是摄像机每秒只拍 24 帧，赶不上车轮转得快，于是高频信息"折叠"回了低频，骗过了你的眼睛。

图像里也一样。当你拍摄密集的格子衬衫，相机分辨率不够时，照片上会出现一些**原本不存在**的彩色波纹——这就是 **摩尔纹**（Moiré pattern）。

```
真实场景: ┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃┃   ← 细密条纹
采样不足: ▓ ▒ ░   ░ ▒ ▓ ▒ ░   ← 出现了"幽灵"低频图案
```

混叠之所以麻烦，是因为一旦发生，**事后无法分辨**哪些是真的、哪些是假象。这就是为什么相机和图像处理算法里，常常先做一道 **抗混叠滤波**（anti-aliasing filter，本质上是先低通滤波再采样），宁可丢掉一些高频细节，也要避免假象污染整个图像。

> 一句话总结：**先低通，再采样；而不是先采样，再后悔。**

### 1.3 图像重建：从离散点回到连续画面

采样把连续变成离散；那当我们要显示、放大、旋转图像时，又需要反过来——从离散点"猜"出中间没采到的位置的值。这个过程叫**图像重建**（或图像插值，interpolation）。

理论上，如果采样满足奈奎斯特定理，**完美重建**是存在的，公式是把每个采样点用 sinc 函数"摊开"再求和：

$$
f(x, y) = \sum_{m}\sum_{n} f[m, n] \cdot \text{sinc}\!\left(\frac{x - m\Delta x}{\Delta x}\right) \text{sinc}\!\left(\frac{y - n\Delta y}{\Delta y}\right)
$$

其中 $\text{sinc}(t) = \dfrac{\sin(\pi t)}{\pi t}$。

听起来很美，但 sinc 函数无限延伸，实际算不动。所以工程上我们用**近似**的插值核，常见的有：

| 方法 | 思想 | 优点 | 缺点 |
|---|---|---|---|
| **最近邻**（Nearest） | 直接抄最近那个像素的值 | 最快、保留原值 | 锯齿严重、像马赛克 |
| **双线性**（Bilinear） | 用最近 4 个像素加权平均 | 平滑、计算快 | 略糊、丢失锐度 |
| **双三次**（Bicubic） | 用最近 16 个像素做三次插值 | 较锐利、平衡 | 慢一些、可能过冲 |
| **Lanczos** | 用截断的 sinc 函数 | 接近理想、锐利 | 慢、振铃 artifact |

```
原始 4×4 ──放大到 12×12──►
         最近邻 (硬边)      双线性 (柔和)       双三次 (清晰)
         ┌─┬─┬─┬─┐         ╱─────╲             ╱╲────╱╲
         │█│ │█│ │         ╱       ╲           ╱  ╲  ╱  ╲
         ├─┼─┼─┼─┤        ╱  渐变   ╲         ╱    ╲╱    ╲
         │ │█│ │█│       —————————————       ——————————————
```

> 💡 **小窗口看大问题**：截图放大用最近邻（保留像素艺术风格），照片缩放一般用双三次或 Lanczos，视频里追求速度多用双线性。**没有最好的算法，只有最适合场景的选择**。

## 第二部分：图像量化

采样解决了"在哪里取值"，量化解决"取到的值怎么存"。

真实世界的亮度可以是任意实数（理论上有无穷多个值），但计算机里一个像素只能存有限位（比如 8 位 = 256 个等级）。怎么把"无穷"压成"有限"？这就是**量化**。

### 2.1 标量量化

**标量量化**（scalar quantization）：每个像素独立量化，互不影响。这是最直观、最常用的方式。

#### 均匀量化

把亮度范围 $[0, V_{\max}]$ 均匀切成 $L$ 段，每段用一个代表值（通常是中点）来代替：

$$
Q(v) = \left\lfloor \frac{v}{\Delta} \right\rfloor \cdot \Delta + \frac{\Delta}{2}, \quad \Delta = \frac{V_{\max}}{L}
$$

其中 $\Delta$ 是 **量化步长**，$L$ 是 **量化等级数**。

如果用 $b$ 位来存一个像素，那么 $L = 2^b$：

- $b = 1$：黑白二值图（只有 0 和 1）
- $b = 4$：16 级灰度
- $b = 8$：256 级灰度，**最常见**
- $b = 16$：65536 级，高动态范围（HDR）、医学影像、深空摄影

```
b=1 (二值)         b=2 (4级)         b=4 (16级)        b=8 (256级)
██▓▓░░            ███▓▒░            ████▓▓▒▒░░       渐变连续
█░██░█            ██▓▒▒░            ███▓▓▒▒░░░░      看起来平滑
└猛烈断层          └有明显台阶        └轻微色带         └眼睛分不清
```

#### 量化误差

量化必然丢失信息，丢失的部分叫 **量化误差**：

$$
e(x, y) = f(x, y) - Q(f(x, y))
$$

对于均匀量化，误差近似服从 $[-\Delta/2, \Delta/2]$ 上的均匀分布，方差为 $\sigma_e^2 = \Delta^2/12$。

衡量量化质量的常用指标是 **峰值信噪比**（PSNR）：

$$
\text{PSNR} = 10 \log_{10}\left(\frac{V_{\max}^2}{\text{MSE}}\right) \quad (\text{dB})
$$

8 位均匀量化的 PSNR 大约 48 dB，对人眼来说已经非常好了。

> 💡 **为什么是 8 位？** 一方面，人眼大约只能分辨 100~200 个灰度级（对数感知），8 位足够覆盖；另一方面，8 位正好是 1 字节，对齐计算机字长，存取和运算都方便。这是一个"刚刚好"的工程妥协。

#### 非均匀量化

人眼对暗部敏感、对亮部不敏感（韦伯-费希纳定律），所以均匀切分其实"亏了"——在亮部花太多等级。**非均匀量化**会在暗部分得细，亮部分得粗：

```
均匀量化:     │─│─│─│─│─│─│─│─│   每段等长
                                    （亮部太精细，浪费）

非均匀量化:   │┃│ │ │  │  │   │    │  暗部密，亮部疏
                                    （贴合人眼感受）
```

这正是 gamma 校正、JPEG DCT 系数量化表背后的思想。

### 2.2 向量量化

标量量化每个像素管自己；**向量量化**（Vector Quantization, VQ）则是**一组像素一起编码**——比如把图像切成 4×4 的小块，每个块当作一个 16 维向量。

为什么要这样？因为相邻像素**高度相关**——一片天空里的像素值都差不多，单独量化每个像素是浪费。如果我们把"天空块"、"草地块"、"皮肤块"这些常见图案做成一本 **码本**（codebook），每个块只需要存一个码字索引就够了。

#### 直觉图解

```
原图分块:                  码本(预先训练):
┌────┬────┬────┐          ┌────┐ ← #1: 蓝天块
│ B1 │ B2 │ B3 │          ├────┤
├────┼────┼────┤          │ ░░ │ ← #2: 浅灰块
│ B4 │ B5 │ B6 │          ├────┤
└────┴────┴────┘          │ ▓▓ │ ← #3: 草地块
                          │... │
每个 Bi 是 16 维向量        共 K=256 个码字

编码: B1→#1, B2→#1, B3→#5, B4→#3, B5→#3, B6→#7
       (只需存6个索引, 比存6×16=96个像素值省太多)
```

#### LBG 算法：训练一本码本

Linde-Buzo-Gray (LBG) 算法是构造码本的经典方法，本质上是 **k-means 在向量空间的应用**：

1. **初始化**：随机选 $K$ 个向量作为初始码字
2. **分配**：把训练集里每个向量分给最近的码字（用欧氏距离）
3. **更新**：每个码字更新为它所分到的所有向量的均值
4. **迭代**：重复 2-3，直到失真不再下降

整体优化目标是最小化总失真：

$$
D = \sum_{i} \min_{k} \|\mathbf{x}_i - \mathbf{c}_k\|^2
$$

> 💡 **VQ 现在还流行吗？** 在传统图像压缩里，VQ 被 DCT/小波变换编码部分取代。但在**深度学习**里，它强势回归——VQ-VAE、VQGAN 用它构造离散的视觉 token，是 DALL·E、Stable Diffusion 早期版本和很多视觉大模型的基础组件。所以这个老技术，正在新时代焕发第二春。

### 2.3 采样、量化参数与数字图像的关系

到这里，我们手里有了三个旋钮：

- **采样密度**：图像分辨率 $W \times H$（宽 × 高，单位是像素）
- **量化等级**：每个像素的位深 $b$
- **通道数**：单通道（灰度）还是多通道（如 RGB 三通道）

**未压缩**的数字图像，存储大小就是这几个量的乘积：

$$
\text{Size} = W \times H \times C \times b \;/\; 8 \quad (\text{字节})
$$

举几个例子让你感受一下：

| 场景 | $W \times H$ | $C$ | $b$ | 大小 |
|---|---|---|---|---|
| 微信头像（缩略图） | 100×100 | 3 | 8 | 30 KB |
| 1080p 照片 | 1920×1080 | 3 | 8 | 6 MB |
| 4K HDR 照片 | 3840×2160 | 3 | 16 | 50 MB |
| 一帧 8K RAW（电影机） | 7680×4320 | 3 | 14 | ~170 MB |

> 这就是为什么我们需要 **图像压缩**（JPEG、PNG、WebP、AVIF...）。一秒 60 帧 4K HDR，未压缩就是 3 GB/秒，没有压缩根本没法工作。

#### 在哪儿"省"？分辨率 vs 位深的权衡

固定文件大小预算下，你可以选择：
- **大分辨率 + 低位深**：图像看起来"大"但有色阶断层（banding）
- **小分辨率 + 高位深**：图像"小"但每个像素颜色过渡更平滑

这没有标准答案，看用途：自然风景照片，分辨率重要；医学/科学影像，位深更重要（要捕捉微弱的对比度差异）。

### 2.4 数字图像的数值描述

经过采样和量化，一张图像最终就是一个**多维数组**。让我们把它彻底拆开看：

#### 单通道灰度图：一个二维矩阵

$$
I = \begin{bmatrix}
I[0,0] & I[0,1] & \cdots & I[0, W-1] \\
I[1,0] & I[1,1] & \cdots & I[1, W-1] \\
\vdots & \vdots & \ddots & \vdots \\
I[H-1,0] & I[H-1,1] & \cdots & I[H-1, W-1]
\end{bmatrix}
$$

每个元素 $I[i, j] \in \{0, 1, \dots, 255\}$（8 位时），0 是纯黑，255 是纯白。

#### 彩色图像：三个二维矩阵堆叠

RGB 图像可以看作三个独立的灰度图——红、绿、蓝通道——堆在一起：

$$
I \in \mathbb{Z}^{H \times W \times 3}
$$

```
        R 通道           G 通道           B 通道
      ┌─────────┐      ┌─────────┐      ┌─────────┐
      │ 红色亮度 │      │ 绿色亮度 │      │ 蓝色亮度 │
      └─────────┘      └─────────┘      └─────────┘
              ╲             │             ╱
               ╲            │            ╱
                ▼           ▼           ▼
              ┌─────────────────────────┐
              │       彩色图像 I         │
              │  shape: (H, W, 3)       │
              └─────────────────────────┘
```

#### 坐标系：一个会咬人的细节

数学里我们习惯 $(x, y)$ 从左下角往上、往右增长；但图像里，**原点通常在左上角**，往下是 $y$（或称 row）正方向，往右是 $x$（或称 col）正方向：

```
数学坐标系:                  图像坐标系:
      y                         ┌─────────► x (col)
      ▲                         │
      │                         │
      │                         ▼
      └──────► x                y (row)
   (原点左下)                 (原点左上)
```

而且 NumPy / OpenCV / PyTorch 访问像素时，**先 row 后 col**，写作 `img[y, x]` 或 `img[i, j]`。但 OpenCV 的某些函数（比如 `cv2.circle((x, y), ...)`）又是先 x 后 y。

> 🐛 **新手最常踩的坑**：把 `(x, y)` 和 `(i, j)` 搞反，导致图像看起来转了 90 度或镜像了。**遇到诡异结果，先怀疑坐标顺序**。

#### 数据类型：不仅是数字

像素值在内存里有不同的"皮"：

| dtype | 范围 | 用途 |
|---|---|---|
| `uint8` | 0~255 | 标准 8 位图像，最常见 |
| `uint16` | 0~65535 | HDR、医学、深空 |
| `float32` | 0.0~1.0（约定） | 深度学习、中间运算 |
| `float64` | 0.0~1.0 | 科学计算，少用 |

> 一个常见 bug：把 `float32`（0~1）的图像直接 `imshow`，看到的不是黑就是白——因为显示函数以为是 `uint8` 在解读。**dtype 错了，一切都错了**。

## 收尾：把整个链路串起来

让我们把所有内容串成一条线：

```
真实世界 (连续 f(x,y))
      │
      │ ① 抗混叠滤波 (避免高频折叠)
      ▼
   低通后的连续信号
      │
      │ ② 采样 (按 Δx, Δy 取点)
      │   满足 fs ≥ 2 f_max
      ▼
   离散信号 f[m, n]
      │
      │ ③ 量化 (每个值压到 2^b 个等级)
      ▼
   数字图像 I ∈ Z^(H×W×C)
      │
      │ ④ 存储 / 传输 / 处理
      ▼
   ┌─────────────────────────────┐
   │ 需要显示/放大时:             │
   │ ⑤ 反量化 (查表得近似值)       │
   │ ⑥ 重建插值 (回到连续画面)     │
   └─────────────────────────────┘
```

每一步都在做一个权衡：
- **采样率**：细节 vs 存储
- **量化位深**：色彩平滑度 vs 存储
- **重建方法**：质量 vs 速度

理解了这条链路，你就理解了 CV 一切的起点——**所有上层算法（卷积、检测、分割、生成）都建立在这些数字之上**。当你后面遇到下采样、上采样、量化感知训练、向量码本时，回头看一眼这篇文章，会感觉旧识新交，一切都连得上。

## 推荐自己动手试试

光看不练假把式。下面这几个小实验，每个 10 分钟，能给你很深的直觉：

1. **采样实验**：用 OpenCV 加载一张图，逐步下采样（`cv2.resize` 到 1/2、1/4、1/8），观察细节如何流失，能否看到混叠。
2. **量化实验**：把图像位深从 8 位强制降到 4、2、1 位（提示：`(img // (256//L)) * (256//L)`），看色阶断层在什么时候开始刺眼。
3. **插值对比**：把同一张小图用最近邻、双线性、双三次放大 5 倍，并排显示，感受三种风格的区别。
4. **造一个摩尔纹**：拍一张细密格子的照片，故意拍得稍微离焦或远一点，往往就能看到摩尔纹。

做完这些，你对"图像是什么"的理解，会和今天完全不一样。
